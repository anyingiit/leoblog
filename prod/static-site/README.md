# Production static site

The artifact runner accepts the Laravel `SitePublicationSnapshot` files only through positional arguments. It requires `<snapshot-directory>/public.json`, `manifest.json`, and a private `publication-identity.json` containing a positive JavaScript-safe generation plus SHA-256 hashes of the two source files. It writes a deterministic tar artifact to the requested output path and never includes the snapshot or identity control file. `OUTPUT_DIR` runner mode is rejected. Runtime comments are never part of the snapshot or generated HTML.

Integration request: configure Laravel's `SubprocessPublicationBuilder` command as `/usr/local/bin/node /owned/static-site/scripts/build.mjs`. The caller appends the snapshot directory and pre-existing output file as positional arguments and forces cwd to the snapshot directory. Do not set `OUTPUT_DIR` for this artifact invocation. The runner verifies identity before starting Astro, derives the HTML version marker from it, selects its own package cwd and installed local Astro executable without `npx`, and builds in an owned temporary staging directory. The coordinator must continue supplying the exact `public_json` and `manifest_json` bytes, their verified identity, and verify the resulting artifact hash. Publication owners should consume the artifact's `manifest.json` and generated route files; no deployment or provider changes are included here.

For read-only source verification, run `node /work/scripts/verify-runner.mjs` in the pinned Node container with container-installed dependencies mounted at `/work/node_modules`. It copies an explicit public-source allowlist into container temporary storage, links only those container dependencies, runs all Node tests (the runner regression itself uses snapshot cwd), and removes its workspace. Do not run this harness against host dependencies. The source bind remains read-only; no environment files or credentials are copied. Exact offline verification and dependency preparation commands are in the Task 3 report.
